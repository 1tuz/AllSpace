# Архитектура — слои и путь запроса

Путь запроса идёт сверху вниз: UI-компонент вызывает обёртку из `packages/core/src/lib`, та — `invokeCapability` или `invokeCommand` из `packages/core/src/transport/transport.ts`. Шим выбирает реализацию по `isTauri()` из `platform.ts`: в десктопе это `tauriTransport.ts` с вызовом `invoke("invoke_capability", { id, input })`, в браузере — `webTransport.ts` поверх HTTP и WebSocket. В Tauri запрос принимает `apps/desktop/src-tauri/src/bridge.rs`, который держит `Registry` в состоянии приложения и вызывает `registry.invoke(&id, input)`. В веб-режиме тот же id приходит в `crates/server/src/api.rs` под сессией (OIDC или dev login). Сам реестр собирается в Tauri-независимом `crates/registry/src/lib.rs` функцией `build_registry_with_paths`, а `apps/desktop/src-tauri/src/capabilities.rs` лишь реэкспортирует её. Дальше id разворачивается в обработчик внутри крейта-владельца: `crates/kube`, `crates/docker`, `crates/jira`, `crates/gitlab`, `crates/bitbucket`, `crates/jenkins`, `crates/correlation`, `crates/llm`. У потоковых операций путь отдельный: ядра в `crates/streams`, события — через `EventSink`. Полная карта — в `docs/ARCHITECTURE.md`.
